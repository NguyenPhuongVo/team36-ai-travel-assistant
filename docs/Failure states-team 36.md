

| Failure type | Trigger | Chatbot response | Accessibility consideration |
| --- | --- | --- | --- |
| Not understood (1st time) | Intent confidence below threshold | "Sorry, I didn't quite understand that. Could you tell me in a few words what you need — for example, 'accessible hotel in Melbourne'?" | Gives a concrete example instead of just repeating the question; no blame placed on the user. |
| Not understood (2nd time) | Second consecutive low-confidence input | "I'm still not sure I've got it. Here are some things I can help with: finding accessible accommodation, checking step-free access, or accessible things to do nearby." + tappable options | Switches from open input to a short, closed list, reducing typing and cognitive load. |
| Not understood (3rd time) | Third consecutive failure | "I'm having trouble helping with this one. I can pass you to a human support agent, or you can call [number] or email [address]." | Caps the loop at three attempts; gives a way out that isn't chat-based, for users who find chat difficult. |
| Empty or unreadable input | Blank message, emoji only, or gibberish | "I didn't get any text I could read there. You can type your message, or use the microphone button if that's easier." | Assumes assistive-tech or input error, not user error; offers an alternative input method. |
| Missing required detail | User asks for options before giving destination or dates | "I can do that — I just need one more thing first. Which city are you travelling to?" | Asks for one missing item at a time, and confirms what it already has. |
| Unrecognised accessibility term | Requirement not in the supported list | "I'm not familiar with that requirement yet, so I can't filter for it. I'll note it down and show it with your results, but please check directly with the property before booking." | Does not silently drop the requirement — the user is told plainly that it wasn't applied. |
| Conflicting requirements | New requirement contradicts an earlier one | "Earlier you mentioned step-free access, and now a ground-floor room with steps. Which would you like me to search for?" | Repeats both back and lets the user resolve it, rather than the system guessing. |
| No results | Zero matches for the full requirement set | "I couldn't find anything matching all of your requirements in Melbourne for those dates. I can widen the search area, try different dates, or show places that meet most of your needs — which would you prefer?" | Never returns an empty screen; always offers at least one next step the user can act on. |
| Partial match only | Results meet some but not all requirements | "These places have step-free access, but I couldn't confirm an accessible bathroom. I've marked what's confirmed and what isn't on each option." | Confirmed vs. unconfirmed is labelled per result, not buried in a general disclaimer. |
| Unverified accessibility data | Source doesn't state accessibility details | "This property hasn't listed its accessibility details, so I can't confirm them. I'd recommend contacting them directly before booking." | Avoids over-promising on safety-critical information; absence of data is never shown as a pass. |
| Search/retrieval failure | Retriever or External Data returns an error | "I can't reach the accommodation listings right now. Your requirements are saved — would you like to try again in a moment?" | Reassures the user their answers aren't lost, so they don't have to start over. |
| AI response failure | Router or Provider times out or errors | "Something went wrong on my end. Please try sending that again." | Owns the error explicitly rather than showing a blank reply or a technical code. |
| Request out of scope | Medical, legal, visa, or insurance advice | "That's outside what I can advise on. For that, I'd suggest speaking with [relevant service]. I can keep helping with accommodation and accessibility questions." | States the boundary once, plainly, and returns the user to what is possible. |
| Asked to decide for the user | "Which one should I book?" | "I can't make that choice for you, but I can put the options side by side so the differences are easier to compare." | Preserves user autonomy, consistent with the Direction stage of your flow. |
| Booking attempt | User asks the chatbot to book or pay | "I'm not able to make bookings. I can give you the link to book directly with the property." | Sets expectations before the user invests effort in the conversation. |
| Unsupported language | Input detected in a language not supported | Message in the detected language: "I can't help in this language yet. I can continue in English, or you can contact support at [details]." | Fails in the user's own language where possible, rather than in English only. |
| Session expiry | Context lost or long inactivity | "I've been away a while and lost the details from earlier. Could you tell me your destination and accessibility needs again?" | Admits the loss rather than continuing on stale or partial information. |
| Broken or dead link | Listing URL fails | "That link doesn't seem to be working. Here's the property's contact details instead, and I'll flag it." | Provides a working alternative in the same turn. |
